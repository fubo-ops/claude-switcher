# 测试用例（Claude 切换器）

> 适用版本：v2.2（macOS 稳定版 + Windows/Linux Beta）
> 自动化回归：`python3 -m unittest discover -s tests -v`
> 手工/破坏性用例请在测试机执行，避免影响生产账号。

## 0. 测试环境

| 项 | 要求 |
|---|---|
| 系统 | macOS 13+（本次验证 macOS 27 / Apple M1） |
| 代理 | Clash Verge / Shadowrocket / sing-box / ClashX / Surge 任一，TUN 可用 |
| Claude | `/Applications/Claude.app` 已安装 |
| 依赖 | python3、Xcode Command Line Tools（CLT-only 可用） |
| 出口 | 非 CN（安装器按出口锁定国家/时区/地区） |

## 1. 用例清单

### A. 安装与升级

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-A01 | 全新安装 | 克隆仓库 → 双击 `installer/安装.command` | 自动识别代理；产出 `~/.local/bin/claude-switch.sh`、`~/.claude-switcher/stun-probe.py`、桌面 `Claude切换器.app`；注册 2 个 LaunchDaemon + 2 个 LaunchAgent；自检 14 项 |
| TC-A02 | CLT-only 编译 | 未装完整 Xcode，仅 CLT，执行安装 | App 编译成功（源码已规避 `@State` 宏） |
| TC-A03 | 重装幂等 | 再跑一次安装器 | 账号存档 `~/.claude-switcher/accounts/` 不受影响；服务重新注册成功 |
| TC-A04 | 权限最小化 | 检查 root 守护文件 | `/Library/Application Support/claude-switcher/*` 为 `root:wheel 755`，用户不可写 |
| TC-A05 | 卸载 | 执行 `installer/卸载.command` | App、脚本、LaunchDaemon/LaunchAgent、配置目录清理；系统时区/IPv6 提示恢复方式 |

### B. 14 项环境审计（Block-on-Fail）

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-B01 | 全绿启动 | TUN/代理正常，打开 App | 14 行全部有状态，13 ok + ASN 可能 warn；显示「环境安全」，可切号 |
| TC-B02 | 审计阻断 | 断开代理/杀 TUN 后打开 App | 出现 `fail` 行，显示「检查未过」，不出现切号按钮（不启动 Claude） |
| TC-B03 | 一键修复 | 在失败态点「一键修复」 | 依次修复代理/TUN、时区、IPv6、保镖、语言、置顶规则、WebRTC；修复后复检转 ready |
| TC-B04 | CLI 总检 | `claude-switch.sh check` | 通过输出 `OK:<出口IP>`；失败输出 `FAIL:<原因>` 且退出码非 0 |
| TC-B05 | 逐项明细 | `claude-switch.sh checkdetail` | 固定 14 行，格式 `名称=ok/warn/fail[:细节]`，UTF-8 不乱码 |

### C. 账号切换（快照隔离）

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-C01 | 首次收编 | 当前有登录态，点「账号 A」 | 当前数据被归档为 A，随后还原并拉起 Claude；`~/.claude-switcher/current` = A |
| TC-C02 | A→B | 点「账号 B」 | Claude 先退出；A 存档；B 数据载入；Claude 以 B 启动；`status` 显示 current=B |
| TC-C03 | B→A | 点「账号 A」 | B 存档；A 载入；Claude 以 A 启动；A 的 sessionKey 等登录态保留 |
| TC-C04 | 数据隔离 | 切号后对比两账号数据目录 | 各账号 `Cookies` 中 `.claude.ai` sessionKey 独立且保留，互不覆盖 |
| TC-C05 | 退出失败保护 | Claude 15s 内无法退出时切号 | 切换中止并提示「Claude 未能退出」，不交换数据（Fail-Closed） |
| TC-C06 | 切换耗时 | 12G 数据 A↔B | 归档为同卷移动（0–4s）；载入为 APFS COW（约 5–15s）；无全量复制 |

### D. Kill-Switch（真实断网）

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-D01 | 保镖周期运行 | 查 `launchctl print system/local.claude-bodyguard` | `runs` 每 10s 递增，`last exit code = 0` |
| TC-D02 | 真实拦截 | Claude 运行中，制造隧道中断（如停 VPN / kill 隧道进程） | ≤10s 内 Claude 进程被终止；`~/Library/Logs/claude-bodyguard.log` 记录「代理离线…已自动关闭 Claude」 |
| TC-D03 | 健康态不误杀 | TUN 正常时观察 | Claude 不被误杀；保镖日志无新增 |
| TC-D04 | 裸连防护边界 | 断网瞬间观察 | 只杀进程、不自动重连（重连由 netguard 负责，见 E 组） |

### E. 网络自动恢复（netguard）

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-E01 | 自动恢复 | 隧道中断 ≥15s 后停止破坏，不做人工操作 | 20s 内自动恢复：优先 `scutil --nc start`，失败再拉起客户端、重启客户端；TUN/出口恢复 |
| TC-E02 | 避免误干预 | 用户主动关闭代理且超过 5 分钟 | netguard 不再尝试拉起 |
| TC-E03 | 留痕 | 查看 `~/Library/Logs/claude-netguard.log` | 记录「隧道中断 Ns，尝试自动恢复」与「恢复成功(策略, Ns)」 |
| TC-E04 | 重试与冷却 | 恢复失败场景 | 每 20s 重试，最多 5 分钟 |

### F. 菜单栏与 UI（v2 动态设计）

| ID | 用例 | 步骤 | 预期 |

| TC-F02 | 菜单功能 | 点盾牌展开 | 状态摘要、当前账号、通过/告警/失败、上次检查、重新检查、打开主窗口、切换 A/B、每 60 秒自动检查、退出 |
| TC-F03 | 自动刷新 | 静置 60s | 后台静默复检，菜单栏状态更新，窗口不闪、不弹扫描条 |
| TC-F04 | 扫描点亮动画 | 首次打开/手动重新检查 | 14 行按约 55ms/行依次点亮，顶部流动扫描条，副标题显示已用耗时 |

### G. 自动更新

| ID | 用例 | 步骤 | 预期 |
|---|---|---|---|
| TC-G01 | 手动更新 | `claude-switch.sh update` | 拉取 main → 校验 `SHA256SUMS` → 无差异输出「已是最新版本」 |
| TC-G02 | 完整性保护 | 篡改下载包或校验清单 | 校验失败即中止，不覆盖本地文件 |
| TC-G03 | 失败回滚 | 新版自检出现 `=fail` | 自动回滚到 `.bak` |
| TC-G04 | 定时任务 | 查 `gui/$(id -u)/local.claude-update` | 已注册，每 12h 执行一次，日志落 `~/.claude-switcher/update.log` |

## 3. 证据与清理

- 自动化命令输出：`checkdetail`、切换日志 `~/Library/Logs/claude-switch.log`、保镖日志 `claude-bodyguard.log`、netguard 日志 `claude-netguard.log`、更新日志 `update.log`
- 测试后清理：临时脚本、截图、`__pycache__`、`.DS_Store` 已删除；**不要清理** `~/.claude-switcher/accounts/`（账号存档）与 `current`/`lastip` 状态
- 破坏性用例（D/E 组）会中断网络并杀 Claude，请在测试机或已确认数据已存档后执行
